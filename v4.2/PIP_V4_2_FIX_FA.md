# اصلاح نسخه ۴٫۲ — خطای Runtime RE10045

تاریخ: ۲۰۲۶-۱۱-۱۰ | پایه: نسخه ۴٫۱ (دست‌نخورده باقی مانده است)

## خطایی که کاربر فرستاد (اسکرین‌شات TradingView، چارت GOLD تایم ۱ دقیقه)

```
Runtime error: RE10045
Error on bar 90: In 'array.get()' function. Index 0 is out of bounds, array size is 0.
at #main():350
```

یعنی در کندل ۹۰، کد خواسته عنصر شماره ۰ یک آرایه خالی را بخواند.

## علت — خط ۳۵۰ دقیقاً چه بود؟

خط ۳۵۰ در نسخه ۴٫۱ این بود، در بخش ساخت اردر بلاک نزولی:

```pine
for i = 0 to array.size(obZones) - 1
    OBZone z = array.get(obZones, i)
```

در کندل ۹۰ اولین جابه‌جایی نزولی اتفاق افتاد، در حالی که هنوز هیچ اردر بلاکی ساخته نشده بود
(آرایه `obZones` خالی بود، اندازه ۰). در Pine حلقه `for i = 0 to -1` با آرایه خالی
هم یک بار با `i = 0` اجرا می‌شود، و `array.get` با اندیس ۰ روی آرایه خالی خطای RE10045 می‌دهد.

این باگ فقط در خط ۳۵۰ نبود؛ همین الگو در ۴ جای کد بود:
بررسی تکراری OB صعودی، بررسی هم‌پوشانی FVG برای OB صعودی،
بررسی تکراری OB نزولی (خط ۳۵۰)، بررسی هم‌پوشانی FVG برای OB نزولی.

## اصلاح در ۴٫۲

هر ۴ حلقه با یک محافظ اندازه آرایه پوشانده شدند:

```pine
if array.size(obZones) > 0
    for i = 0 to array.size(obZones) - 1
        OBZone z = array.get(obZones, i)
```

حالا وقتی آرایه خالی است، حلقه اصلاً اجرا نمی‌شود.

حلقه‌های نزولی (به‌روزرسانی OB و FVG) از اول داخل `if array.size(...) > 0` بودند و سالم‌اند.

## بک‌تست هم همین تله را داشت

در فایل بک‌تست، حلقه آمار (`for i = 0 to n - 1`) اگر هیچ معامله‌ای بسته نشده باشد
(`n = 0`) همین خطا را می‌داد. در نسخه ۴٫۲ بک‌تست هم با `if n > 0` محافظت شد.
فایل: `Pip_XAUUSD_Backtest_v4_2.pine`
