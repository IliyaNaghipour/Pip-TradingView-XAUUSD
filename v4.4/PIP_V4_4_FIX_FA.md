# اصلاح خطای کامپایل بک‌تست — نسخه ۴٫۴

**فایل:** `Pip_XAUUSD_Backtest_v4_4.pine` (پوشه `v4.4/`)
**مبنا:** `Pip_XAUUSD_Backtest_v4_3.pine` (۳۸۹ خط، بدون تغییر باقی ماند)
**تاریخ:** ۲۰۲۶-۱۱-۱۰ — ایلیا در Pine Editor خط ۳۲۸ را با خط قرمز دید و گفت «این خط مشکل داره».

## خطای دقیق

```pine
int n = strategy.closedtrades.size(strategy.closedtrades)   // خط ۳۲۸ در ۴٫۳
```

## علت ریشه‌ای — تغییر API در Pine v6

این خط با الگوی Pine **v5** نوشته شده بود، ولی فایل `//@version=6` است:

- در Pine v6 خودِ متغیر `strategy.closedtrades` **تعداد معاملات بسته‌شده** است (عدد صحیح).
  راهنمای رسمی مهاجرت به v6 و مرجع توابع `strategy.*` همین را می‌گویند:
  `strategy.closedtrades` — «Number of trades, which were closed» و در مثال‌های v6
  مستقیم به‌عنوان شمارنده استفاده می‌شود (`strategy.closedtrades - 1` برای آخرین معامله).
- تابع `strategy.closedtrades.size(trade_num)` در v6 چیز دیگری است: **حجم (تعداد واحد) یک
  معامله مشخص** را برمی‌گرداند و نوع برگشتی‌اش `series float` است — نه تعداد معاملات.
- پس خط ۳۲۸ دو مشکل داشت: (۱) به‌جای تعداد معاملات، حجم معامله‌ای با شماره‌ای
  ناموجود را می‌خواست؛ (۲) مقدار اعشاری (float) را به متغیر صحیح (`int n`) نسبت
  می‌داد — و کامپایلر دقیقاً همین خط را خطا گرفت.

## اصلاح در ۴٫۴ (فقط همین یک خط + به‌روزرسانی شماره نسخه)

```pine
int n = strategy.closedtrades
```

## چیزهایی که چک شد و سالم بودند

- `strategy.closedtrades.profit(i)` ،`entry_price(i)` ،`exit_price(i)` ،`entry_comment(i)`
  در Pine v6 درست‌اند: همه فقط شماره معامله (`trade_num`) را می‌گیرند و نیازی به
  آرگومان اول ندارند. پس خط‌های ۳۳۷ به بعد مشکلی ندارند و دست نخوردند.
- بقیه فایل نسبت به ۴٫۳ تغییری نکرده است (۱۸ اصلاح دور اول و دوم ۴٫۳ سر جایشان‌اند).

## چک‌های استاتیک انجام‌شده روی ۴٫۴

- `//@version=6` در خط اول؛ ۰ تب؛ ۰ مورد `closedtrades.size(`؛ شماره نسخه ۴٫۴ در عنوان،
  shorttitle و سربرگ جدول؛ فایل ۴٫۳ دست‌نخورده (md5: `fd14c4c727f96a3c9e72cbcc9677fa9a`).
